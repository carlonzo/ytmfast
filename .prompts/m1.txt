- rodio 0.22 with default-features=false and features ["playback","symphonia-aac","symphonia-isomp4"] decodes that m4a via `rodio::Decoder::try_from(std::fs::File)`, 44.1 kHz stereo, correct total_duration(). Look up the exact rodio 0.22 API in ~/.cargo/registry/src after `cargo fetch` (OutputStream / Sink / Player names changed across versions; e.g. `rodio::OutputStreamBuilder::open_default_stream()` and `rodio::Sink::connect_new(stream.mixer())` in 0.21+; verify, do not guess). Sink supports pause/play/set_volume/try_seek/get_pos/empty.

## File layout (exactly these source files)
- src/main.rs: eframe setup (window title "ytmfast", ~1200x800), image loaders, App struct holding UI state + backend handle; poll events each frame (try_recv loop); draw UI; views push `Action`s into a Vec during drawing and the App applies them AFTER drawing.
- src/backend.rs: spawns a std::thread that owns a tokio multi-thread runtime. `Cmd` enum in (std::sync::mpsc::Sender<Cmd>), `Event` enum out (std::sync::mpsc + `egui::Context::request_repaint()` after every send). Wraps rustypipe. Maps rustypipe types to an own small `Track { id, title, artist, album, duration_secs: u32, thumb_url: Option<String> }` so the UI never touches rustypipe types. Cmds for M1: Search(String), Fetch(Track) (download audio via audio.rs fetch). Events: SearchResults{query, tracks} / SearchError(String), Ready{id, path} / FetchError{id, msg}. Each Cmd is handled in a spawned tokio task so a slow download never blocks a search. Ignore stale results (search results whose query != current query; Ready for an id that is no longer the current track should not start playback).
- src/audio.rs:
  * `fn cache_path(id) -> PathBuf` = ~/.cache/ytmfast/audio/<id>.m4a (create dir).
  * `fn ytdlp_args(id: &str, out: &Path, cookies: Option<&Path>) -> Vec<String>` (pure, unit-tested).
  * `async fn fetch(id, cookies) -> Result<PathBuf, String>`: if cache file exists return it; else run yt-dlp (tokio::process::Command) writing to `<id>.m4a.part` ... NOTE yt-dlp appends its own extensions/handles .part itself, so pass `-o <dir>/<id>.dl.m4a`-style explicit output and then rename to the final path only after success; ensure the final name never exists in a half-written state; validate the id is [A-Za-z0-9_-]{11} before building the path/command. Capture stderr for the error message (truncate).
  * `Player`: owns the rodio output stream + Sink (lives on the UI thread; rodio ops are non-blocking; opening/decoding a local file is fine on UI thread but prefer opening the decoder... acceptable either way since the file is local and already fully downloaded). Methods: play_file(path) (stop previous, append decoder, play), toggle_pause, seek(Duration), position(), duration (from decoder total_duration, fall back to Track.duration_secs), set_volume(f32), is_finished().
  * `Queue { tracks: Vec<Track>, order: Vec<usize>, pos: usize, shuffle: bool, repeat: Repeat{Off,All,One} }` with pure methods: new(tracks, start_index), current(), next() -> Option<&Track> (auto-advance semantics: repeat One returns same track for auto-advance; a user "next" press skips even in repeat One — expose `next(user: bool)` or two methods), prev() (if position > 3 s restart the track instead — that check belongs in the App, queue prev just goes back; at index 0 with repeat Off stays at 0), jump(index), set_shuffle(bool) (keeps current track current, shuffles the rest), cycle_repeat(). End of list with repeat Off -> None (playback stops); repeat All wraps.
- src/ui.rs: theme + views for M1 only.

## Hard rules

- No unwrap() on fallible runtime paths (network, IO, audio device). If no audio device is available, show an error but don't crash.
- No stream/player calls on rustypipe.
- Never log or print cookie contents.
- Don't implement milestone 2/3 features (sidebar, home shelves, album/artist pages, queue panel, MPRIS, auth dialog, prefetch, persistence). A `cookies: Option<PathBuf>` field passed through to ytdlp_args is enough (None in M1).
